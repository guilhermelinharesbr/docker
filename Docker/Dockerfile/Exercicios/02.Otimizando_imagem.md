```txt
ENV SITE="www.teste.com.br"

```

Obs: O Docker trabalho com cache de camadas, se uma camada não é modificada, então Docker aproveita o cache de camada e não faz novamente o build desta camada específica. 

Obs2: Se uma camada é modificada o Docker, fará o build dela e de todas as camadas abaixo dela.

Continuando nos comandos:
```bash
# Fazendo o build, esse processo demora alguns minutos:
docker build -t meu-app-python:v2 .
# Fazendo novamente o build, apenas para mostrar que com o cache do Docker o processo é bem mais fácil:
docker build -t meu-app-python:v3 .
# Listando a imagem criada:
docker image ls -a
# Obs: O nome dela ficou meu-app-python:v2 e o tamanho dela foi de 1.58GB e a v1 era 847MB.
```

Modificado o arquivo _/home/administrator/projeto/curso-docker-essencial-card-business/card-business/templates/cartao.html_, apenas duplicando a linha `<p><strong>Site:</strong> {{ site }}</p>`. 

Continuando nos comandos:
```bash
# Fazendo novamente o build, para mostrar como fica o cache após atualizar algum arquivo:
docker build -t meu-app-python:v4 .
# Obs. O cache só foi aproveitado das camadas:
# "FROM python:3.9"
# "WORKDIR /app" 
# A partir do "COPY . ." já não tinha mais cache,
# pois teve uma modificação em um arquivo 
```

--

Para otimizar o COPY, pode-se passar primeiro as bibliotecas e depois os arquivos, será mostrado abaixo que a primeira camada de COPY pega o arquivo requirements.txt, onde neste arquivo tem todas as bibliotecas, já o segundo COPY pega os demais arquivos. Essa estratégia de otimização válida, pois dificilmente as bibliotecas são modificadas, já o código é bastante modificado:

Dockerfile **otimizado parte 2**:
```txt
# cat Dockerfile

FROM python:3.9
WORKDIR /app
COPY requirements.txt .
RUN pip3 install --no-cache-dir -r requirements.txt
EXPOSE 8080 
ENV LOGOMARCA="https://cdn.discorapp.com/attachments/10744800287853858995/1110782090032709643/logomarca-azul-1000x235.png"
ENV FOTO="https://cdn.discorapp.com/attachments/1074800287853858997/1113253295033696337/image.png"
ENV NOME="Guilherme"
ENV IDADE="20"
ENV EMAIL="teste@dominio.com.br"
ENV PROFISSAO="Analista de TI"
ENV SITE="www.teste.com.br"
COPY . .
CMD [ "python3", "app.py" ]
```

Obs: Agora com o Dockerfile otimizado parte 2, tem 12 camadas que podem ser reutilizadas em uma build, onde tiverem alterações no código, sendo elas:
- FROM python:3.9
- ... até
- ENV SITE="www.teste.com.br"

Obs2: As camadas que MAIS são modificadas devem ser jogadas para parte de baixo do Dockerfile, já as que MENOS são modificadas devem ser jogadas para parte de cima do Dockerfile.

Continuando nos comandos:
```bash
# Fazendo novamente o build, para mostrar como fica o cache após otimizar o COPY:
docker build -t meu-app-python:v5 .
# Obs. o processo de build foi muito mais rápido
```

--

Agora será otimizada imagem base, pois como pode ser visto mais acima neste arquivo, quando a imagem base era Ubuntu a imagem após o build ficava com 847MB e depois que passou a imagem base do próprio Python a imagem ficou 1.58GB. Será usado o S.O. **Alpine**.

Para usar uma imagem do Python 3.9 com Alpine, basta ir no DockerHub e pesquisar em Tags por **3.9-alpine**. Boa parte das imagens no Docker Hub possuem uma versão utilizando alpine.

Continuando nos comandos:
```bash
docker image pull alpine
# Mostrando que uma imagem do alpine latest é bem pequena, com apenas 12.7MB:
docker image ls
```

Dockerfile **otimizado parte 3**:
```txt
# cat Dockerfile

FROM python:3.9-alpine
WORKDIR /app
COPY requirements.txt .
RUN pip3 install --no-cache-dir -r requirements.txt
EXPOSE 8080 
ENV LOGOMARCA="https://cdn.discorapp.com/attachments/10744800287853858995/1110782090032709643/logomarca-azul-1000x235.png"
ENV FOTO="https://cdn.discorapp.com/attachments/1074800287853858997/1113253295033696337/image.png"
ENV NOME="Guilherme"
ENV IDADE="20"
ENV EMAIL="teste@dominio.com.br"
ENV PROFISSAO="Analista de TI"
ENV SITE="www.teste.com.br"
COPY . .
CMD [ "python3", "app.py" ]
```

Obs: Foi mudada apenas a instruções FROM para **python:3.9-alpine**.

Continuando nos comandos:
```bash
# Fazendo novamente o build, para mostrar como fica usando uma imagem do python com base Alpine:
docker build -t meu-app-python-alpine:v1 .
# Mostrando que uma imagem do alpine latest é bem pequena, com apenas 12.7MB:
docker image ls
```

Obs: Foi observado que ao utilizar uma imagem do Python com base Alpine a imagem ficou apenas com **94.1MB**, sendo que antes quando a imagem base era Ubuntu a imagem após o build ficava com 847MB, e depois que passou a imagem base do próprio Python a imagem ficou 1.58GB.

Continuando nos comandos:
```bash
# Criando um container a partir da imagem recém criada com Alpine de base
docker run -dit --name container-meu-app-alpine -p 8080:8080 meu-app-python-alpine:v1
docker container ls -a
```
